# 1.5.0-ko.0 기기 테스트 계획

upstream `v1.5.0` 병합 결과물을 실기기에 올려 검증하기 위한 문서.
병합 커밋: `9865f918` / 브랜치: `merge/upstream-1.5.0` (베이스: `origin/release/korean` = 1.3.0-ko.1 + 15 커밋)

## 1. 빌드 상태 (호스트에서 검증 완료)

| 환경 | 결과 | Flash 사용 | 비고 |
|------|------|-----------|------|
| `default` | SUCCESS | 6,889,617 / 6,946,816 (99.2%) | 헤드룸 57 KB |
| `gh_release` | SUCCESS | 6,854,739 / 6,946,816 (98.7%) | `firmware.bin` = 6,868,768 B |
| `sticky` (S3) | SUCCESS | 6,735,467 / 6,946,816 (97.0%) | |
| `gh_release_rc`, `slim` | 미빌드 | — | 동일 플래그 계열, 릴리즈 전 확인 필요 |

- clang-format 21 위반 0건 (변경된 C/C++ 225개 파일 전부 확인)
- `korean.yaml` 439/439 자체 번역, fallback 0

### 플래시 크기 경고 (릴리즈 차단 요소)

`gh_release`의 `firmware.bin`이 **6,868,768 B** 로, 순정 CrossPoint OTA app 파티션
한계인 **6,553,600 B (6.25 MB)** 를 **약 307 KB 초과**했습니다.

- 1.3.0-ko.1 기준 6,460,336 B → 1.5.0 기능 추가분 약 +408 KB
- 이 상태로 태그를 만들면 잠긴 X4는 **단일 OTA 설치가 불가**하고,
  2단계 경로(순정 CrossPoint로 OTA → SD 카드로 KO 플래시)를 써야 합니다.
- `CP_HYPHENATION_LANGS=0` 와 시리얼 로그 제거는 이미 적용된 상태이며, 추가 절감은
  기능 삭제가 필요합니다 (사전 / OPDS / KOReader sync / 웹 UI 중 선택).
- 자세한 배경: `docs/firmware-size-budget.md`

**릴리즈 전에 결정 필요**: 기능을 잘라 6.25 MB 아래로 맞출지, 아니면 이번 버전은
2단계 설치를 안내할지.

## 2. 플래싱 방법

`open-x4-sdk` 서브모듈이 `freeink-sdk` 로 교체되었으므로 클린 체크아웃에서는 서브모듈
초기화가 반드시 필요합니다.

```bash
git submodule sync
git submodule update --init --recursive freeink-sdk
```

### 개발 빌드 (권장, 시리얼 로그 포함)

```bash
pio run -e default -t upload
python3 scripts/debugging_monitor.py
```

### 릴리즈 후보 검증

```bash
pio run -e gh_release
# .pio/build/gh_release/firmware.bin 을 SD 카드로 복사해 기기에서 SD 업데이트
```

### 롤백 준비

1.3.0-ko.1 펌웨어 바이너리를 미리 SD 카드에 준비해 두세요. 이번 병합은 설정/캐시
포맷을 모두 바꾸므로 되돌릴 때 필요합니다.

## 3. 테스트 전 준비 (중요)

이번 병합은 **설정 파일과 섹션 캐시 포맷을 모두 변경**했습니다.

| 항목 | 변경 | 조치 |
|------|------|------|
| 설정 저장 | `JsonSettingsIO` 삭제 → `PersistableStore` 기반 `CrossPointSettings::toJson/fromJson` | 기존 `settings.json` 은 그대로 읽힘. 단 `settings.bin`(1.2.x 레거시) 마이그레이션은 **삭제됨** |
| 섹션 캐시 | v26 → **v37** | 모든 책이 자동 재색인됨 (수동 삭제 불필요, 다만 첫 열기가 느림) |
| 진행률 | 페이지 번호 → 콘텐츠 오프셋 기반 | 기존 진행률은 유지되나, 레이아웃 변경 시 위치 복원 방식이 달라짐 |

권장 준비:
1. 현재 SD 카드의 `.crosspoint/settings.json` 을 백업
2. 테스트 계정으로 `.crosspoint/` 를 통째로 지운 클린 상태 1회 + 기존 캐시 유지 상태 1회, 두 경로 모두 확인

## 4. 한국어 기능 회귀 테스트 (최우선)

병합에서 가장 위험한 영역입니다. 순서대로 확인해 주세요.

### 4.1 기본 폰트 / SD 폰트

- [ ] `customFontPath` 가 빈 상태에서 부팅 → EPUB 본문이 **KoPub 바탕**으로 렌더링
- [ ] 설정 화면에 upstream **"Font Family" (NotoSerif/NotoSans) 선택기가 없음**
- [ ] 설정 > 읽기 > 글꼴 → `FontSelectionActivity` 진입, SD의 `.epdfont` 목록 표시
- [ ] 목록이 `/fonts`, `/.fonts`(숨김), 패밀리별 하위 폴더를 모두 스캔
- [ ] SD 폰트 선택 후 본문이 해당 폰트로 렌더링, 재부팅 후에도 유지
- [ ] 설정 목록에서 현재 적용된 리더 폰트 이름이 값으로 표시
- [ ] 설정 > 화면 > 시스템 글꼴 → UI 전체가 선택한 SD 폰트로 바뀜
- [ ] 시스템 글꼴 적용 시 한자/가나가 표시되고 Pretendard 폴백이 동작
- [ ] **한자 다수 포함 문서**에서 글리프 깨짐 없음 (ko.20에서 고친 per-font 캐시 회귀 확인)
- [ ] Bold 변형이 없는 SD 폰트에서 굵은 글씨가 synthetic bold로 표시

> 이번 병합에서 `SdFontFamily::getTextDimensions` 의 combining-mark 계산을 upstream의
> 새 `combiningMark::Anchor` API로 바꿨습니다. 측정과 렌더가 어긋나면 글자 간격이
> 틀어지므로 **자간/줄바꿈 위치**를 특히 눈여겨봐 주세요.

### 4.2 줄바꿈 / 조판

- [ ] `characterWrap` 기본값 ON, 한국어 본문이 아무 글자에서나 줄바꿈
- [ ] `characterWrap` ON 상태에서 **하이픈이 삽입되지 않음**
- [ ] `characterWrap` OFF + 하이픈 ON → 영문 문서에서 하이픈 동작
- [ ] `paragraphIndent` ON → 첫 줄 들여쓰기(U+3000) 1회만 적용 (**들여쓰기 2배 아님**)
- [ ] `paragraphIndent` ON + 문단 간격 OFF 조합에서도 들여쓰기 1회
- [ ] 줄 간격 좁게/보통/넓게 = 1.00 / 1.20 / 1.40 배 (1.2.0-ko와 동일한 느낌)
- [ ] SD 폰트로 바꿔도 줄 간격이 동일 (upstream의 폰트별 조건 분기가 되살아나지 않았는지)
- [ ] 정렬(양쪽/왼쪽/가운데/오른쪽/책 스타일) 전환 후 재색인 정상

### 4.3 캐시 무효화

### 4.4 리더 메뉴

## 5. upstream 1.5.0 신규 기능 (신규 검증)

한국어 빌드에서 처음 동작하는 기능들입니다.

### 5.1 점진적(incremental) 섹션 색인 — 가장 큰 변화

- [ ] 매우 큰 챕터가 있는 EPUB에서 첫 페이지가 곧바로 표시되고 나머지가 백그라운드로 색인
- [ ] 색인 중에도 페이지 넘김이 막히지 않음
- [ ] 색인 중 리더를 나가거나 절전 진입 → 재진입 시 이미 색인된 페이지가 즉시 표시(partial 캐시)
- [ ] partial 캐시 상태에서 "X / Y 페이지" 표시가 비정상적으로 튀지 않음
- [ ] 색인 중 강제 절전/전원 차단 후 재부팅 → 손상된 캐시로 오동작하지 않음
- [ ] 색인 진행 중 `ESP.getFreeHeap()` 이 50 KB 아래로 떨어지지 않음 (시리얼 모니터)

### 5.2 사전 (신규)

- [ ] SD `/dictionaries/<name>/` 에 사전 배치 → 설정 > 읽기 > 사전 에 목록 표시
- [ ] 리더 메뉴 > 사전 찾기 → 단어 선택 화면
- [ ] 한국어 단어 선택 및 뜻풀이 표시 (한국어 사전 파일로)
- [ ] 사전 미설정 시 "사전이 설정되지 않음" 안내
- [ ] 사전 조회 중 메모리 부족으로 크래시하지 않음
- [ ] **사전 폰트 렌더링**: upstream의 SD 폰트 prewarm 호출을 제거했으므로,
      뜻풀이 텍스트가 SD 리더 폰트로 정상 렌더링되는지 확인

### 5.3 책갈피

- [ ] 리더 메뉴 > 책갈피 전환 → 추가/삭제 토스트
- [ ] 책갈피가 있을 때만 "책갈피" 목록 항목 표시
- [ ] 책갈피로 이동 시 정확한 위치 복원
- [ ] Confirm 길게 누르기 동작을 "책갈피"로 설정 후 동작

### 5.4 기타 신규

- [ ] 저장된 Wi-Fi 자동 연결
- [ ] 숨겨진 SSID 수동 추가
- [ ] 책 끝 화면의 "다음 책" 추천
- [ ] OPDS 다운로드 폴더 / 파일명 형식 설정
- [ ] KOReader 스마트 동기화, 메타데이터 전송 옵션

- [ ] 이미지 지연 추출: 이미지 포함 페이지 첫 렌더가 정상

## 10. 이번 병합에서 내가 판단한 사항 (검토 요청)

기계적 병합이 아니라 판단이 들어간 부분입니다. 이견이 있으면 되돌릴 수 있습니다.

| # | 판단 | 이유 |
|---|------|------|
| 1 | upstream cpfont 엔진 삭제, 한국어 `.epdfont` 엔진 유지 | 사용자 지시 (46c01385과 동일 방침) |
| 2 | `TextSettingsActivity` / `TextSettingsPreview` 삭제 | Family/Size 탭이 cpfont 레지스트리 의존. 한국어는 ReaderOptions로 이미 커버, 플래시 예산 초과 상태 |
| 3 | `JsonSettingsIO` 삭제, upstream `PersistableStore` 채택 | upstream이 동일 기능을 흡수. 부작용: **1.2.x `settings.bin` 마이그레이션 상실** |
| 4 | `fontSize` enum → upstream `fontPointSize` | upstream 코드가 광범위하게 의존. 한국어 리더 폰트 선택은 영향 없음(호환 목적 보존) |
| 5 | 신규 upstream 언어 6종(arabic/bosnian/indonesia/norwegian/portuguese-PT/vietnamese) 미포함 | fork 정책(en+ko만) + 플래시 예산 |
| 6 | Finnish 하이픈을 `CP_HYPHEN_LANG_FI` 로 게이팅 | 한국어 플래시 게이팅 체계 유지 |
| 7 | Korean 방식의 "다음 챕터 silent indexing" 삭제 | upstream의 백그라운드 점진 색인이 상위 호환 |
| 8 | `CP_HYPHENATION_LANGS=0` 을 default/rc/slim/sticky 로 확대 | 그러지 않으면 app 파티션 초과로 빌드 실패(CI 포함) |
| 9 | 섹션 캐시 버전 v37 (upstream v36 다음 번호) | 한국어 두 플래그가 헤더에 추가되어 레이아웃이 다름 |
| 10 | 사전 화면의 SD 폰트 prewarm 호출 제거 | cpfont advance table 전용 API. `SdFont` 는 자체 캐시로 온디맨드 처리 |
| 11 | 한국어 OTA 2단계 경로 유지 (upstream의 `esp_ota` 직접 기록 미채택) | X4 efuse-blk-rev 오탐 회피가 이 경로의 존재 이유 |
